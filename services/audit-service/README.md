# Audit Service – Scholarship Contract System

## Overview
The **Audit Service** is the system-level auditing microservice of the Scholarship Contract Management System.

Its purpose is to **persist immutable audit events** generated by the platform, enabling:
- Traceability
- Accountability
- Post-incident analysis
- Compliance validation

This service is **fully event-driven** and does **not expose business APIs**.

---

## Responsibilities
- Consume domain events from Kafka
- Persist audit logs in MongoDB
- Provide immutable event storage
- Enable system traceability
- Support auditing and compliance requirements
- Expose minimal health and documentation endpoints

---

## Architecture

### Applied Architecture Pattern
- **Event-Driven Architecture (EDA)**
  - Business services emit domain events to Kafka
  - The Audit Service consumes selected events
  - Events are persisted as immutable audit records

### Design Principles
- **Single Responsibility Principle (SRP)** – auditing only
- **Loose Coupling** – no HTTP dependencies on business services
- **Asynchronous Communication** – non-blocking audit logging
- **Event Immutability** – audit records are append-only
- **Scalability** – Kafka consumer groups allow horizontal scaling

The Audit Service contains **no business logic** and **no orchestration logic**.

---

## Tech Stack
- **Framework**: NestJS
- **Language**: TypeScript
- **Database**: MongoDB
- **Message Broker**: Apache Kafka
- **ODM**: Mongoose
- **Runtime**: Node.js
- **API Documentation**: http://localhost:3008/docs

## Database Usage (MongoDB)

MongoDB is used to store **audit events** due to:
- Schema flexibility
- High write throughput
- Append-only audit patterns
- Natural fit for event documents
